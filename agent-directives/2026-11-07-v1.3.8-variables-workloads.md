## 2. What the change is, and why

### Bug 1: dashboard variables were not exported

The `DashboardEntity` selection in both exporters had no `variables` field. Widget NRQL keeps its `{{name}}` placeholders, but the archive carried no definition of what `name` is: its type, NRQL source, enum items, default value or replacement strategy. Templated dashboards could not be converted faithfully, and the gap was invisible. The dashboard-level `description` wasn't selected either (only `pages[].description` was).

**Fix:** add `description` and this block to the `DashboardEntity` selection, next to `owner { … }`:

```graphql
variables {
  name title type isMultiSelection replacementStrategy
  defaultValues { value { string } }
  items { title value }
  nrqlQuery { accountIds query }
  options { excluded hiddenOnVariablesBar ignoreTimeRange showApplyAction }
}
```

These are all the fields of `DashboardVariable`, checked against the NerdGraph schema on 2026-11-07. `type` ∈ `NRQL | ENUM | STRING`; `replacementStrategy` ∈ `DEFAULT | IDENTIFIER | NUMBER | STRING`.

### Bug 2: workload definitions were not exported

The exporters fetch workloads as `WorkloadEntity`, which returns **metadata only**: guid, name, timestamps, permalink, tags. Membership and health rules live elsewhere, on `actor.account(id).workload.collections` (`WorkloadCollection`). Every exported workload therefore arrived with **no entity search queries, no static entities and no status rules**, so a converter could only recreate an empty shell.

`EXPORT-SCHEMA.md` documented a workload `entitySearchQuery` (a string) plus `scopeAccounts`. The exporter never produced it, and `@dma/newrelic-converter` doesn't read it: `NRWorkload` expects `entitySearchQueries: [{query}]`, `entityGuids: string[]` and `description`.

**Fix:** after the existing workload batch loop and before `workloads.json` is written, run one more query per account and merge the results into each workload by `guid`:

```graphql
{ actor { account(id: ACCOUNT_ID) { workload { collections {
  guid description
  entitySearchQueries { query }
  entities { guid }
  scopeAccounts { accountIds }
  statusConfig {
    automatic {
      enabled
      remainingEntitiesRule { rollup { strategy thresholdType thresholdValue } }
      rules {
        entitySearchQueries { query }
        entities { guid }
        rollup { strategy thresholdType thresholdValue }
      }
    }
    static { description enabled status summary }
  }
} } } } }
```

Merged fields:
- `description`
- `entitySearchQueries` (default `[]`)
- `entityGuids` = `entities[].guid` (default `[]`)
- `scopeAccounts`
- `statusConfig`

If the query fails, log a warning (*"Workload definitions query failed — workloads exported WITHOUT entity queries or status rules"*) and still write the metadata. Don't fail the export.

**Schema traps found on the way. Don't repeat them:**
- `WorkloadEntity.collection` exists but is an `EntityCollection` (a different type). It doesn't carry these fields.
- `WorkloadRollup` has **no** `groupBy` field. Selecting it fails the whole query.

### Verified against NerdGraph on 2026-11-07, test account (90 dashboards, 5 workloads)

Both the bash and the PowerShell exporter were run live, and their output was **identical**:

| | Before (v1.3.7) | After (v1.3.8) |
|---|---|---|
| Dashboards with `variables` | 0 (field absent) | 2 of 90. The templated one carries 3: `services` (NRQL, multi-select, `STRING`), `severity` (ENUM, 4 items), `time_range` (STRING, `IDENTIFIER`) |
| Workloads with `entitySearchQueries` | 0 / 5 | 5 / 5 (1 query each) |
| Workloads with `statusConfig.automatic.rules` | 0 / 5 | 5 / 5 (5 rules each) |
| Converter `WorkloadConverter` output | empty name-only shell | carries the NR query (as a manual-translation hint) and the description |

**Known issue, unchanged and NOT fixed here:** the `.ps1` service-level export still uses the pre-v1.3.3 `account.serviceLevel` shape, so `-All` / `-ServiceLevels` fail on Windows. Keep the existing known-issue note.

+## [1.3.8] - 2026-11-07
+
+### Fixed
+
+- **🔴 Dashboard variables were not exported.** The `DashboardEntity` selection had no `variables` field. Widget queries kept their `{{name}}` placeholders, but the archive had no definitions to resolve them against. The selection now includes `variables` with every `DashboardVariable` field: `name title type isMultiSelection replacementStrategy`, `defaultValues { value { string } }`, `items { title value }`, `nrqlQuery { accountIds query }` and `options { excluded hiddenOnVariablesBar ignoreTimeRange showApplyAction }`. The dashboard-level `description` is now selected too.
+- **🔴 Workload definitions were not exported.** `WorkloadEntity` returns metadata only. Membership and health rules live on `account.workload.collections`, which the exporter never queried, so every workload arrived with no entity search queries, no static entities and no status rules. A third phase now queries the account's collections and merges these fields into each workload by `guid`:
+  - `description`
+  - `entitySearchQueries [{query}]`
+  - `entityGuids` (from `entities[].guid`)
+  - `scopeAccounts`
+  - `statusConfig`: automatic rules and rollups, plus static statuses
+
+  The field names match what `@dma/newrelic-converter` already reads (`NRWorkload.entitySearchQueries`, `entityGuids`, `description`). If the definitions query fails, the exporter logs a warning and still writes the metadata.
+
+  **Verified against NerdGraph** on test account 8018100, with both the `.sh` and the `.ps1` (`.ps1` v1.0.4), and identical output from each:
+  - 90 dashboards exported; the two with variables carry all their definitions (3 on the templated dashboard: an NRQL multi-select, an ENUM and a STRING `IDENTIFIER`)
+  - all 5 workloads carry 1 entity search query and 5 automatic status rules
+  - the converter now passes the workload query and description through; previously both were missing
+

+
+- `EXPORT-SCHEMA.md`: the dashboards section documents `description` and `variables`. The workloads section had shown an `entitySearchQuery` string that the exporter never produced and the converter never read; it now documents `entitySearchQueries`, `entityGuids`, `description`, `scopeAccounts` and `statusConfig`.
