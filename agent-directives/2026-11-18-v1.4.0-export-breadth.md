## 3. The change, by intent

Everything is in one new section of `dma-newrelic-export.sh`, **EXPORT BREADTH (v1.4.0)**, placed just before the RBAC section, plus small hooks elsewhere. Every query was run against the live test account on 2026-11-18, except the two marked schema-only.

### 3.1 Shared helpers (new)

- `entity_search_all QUERY`: runs `entitySearch` across all pages (cursor on `results`, as in v1.3.5+) and prints `[{guid,name,type,domain,accountId,tags}]`.
- `entity_details_batched GUIDS SELECTION`: runs `actor.entities(guids:)` in batches of `$ENTITY_FETCH_BATCH`.
- `paged_account_list ACCOUNT QUERY PATH FIELD`: pages an account-scoped result set that takes `cursor:` and returns `nextCursor`.
- `JQ_TAG_DEF`: a jq `tag($k)` helper that lifts an entity tag value.

All of them use `nerdgraph_query_vars` (variables, no string-built queries). On a failed page they keep what they collected, log the failure and return 1.

### 3.2 `--alerts`: two new NerdGraph files

**`alerts/translated_conditions.json`** comes from `asNrqlConditionsSearch`. This query returns **every** alert condition rendered as an NRQL condition, in the same `terms` / `signal` / `expiration` shape as `nrql_conditions.json`, plus `sourceProduct` (`APM | BROWSER | INFRASTRUCTURE | MOBILE | NRQL | SERVERS | SYNTHETICS`). The NRQL ones are already in `nrql_conditions.json`, so the exporter keeps only `sourceProduct != "NRQL"`. The query pages (the page size is 50; the test account has 59 conditions).

```graphql
query ($id: Int!, $cursor: String) { actor { account(id: $id) { alerts {
  asNrqlConditionsSearch(cursor: $cursor) { nextCursor totalCount nrqlConditions {
    id name description enabled policyId type sourceProduct entityGuid runbookUrl
    titleTemplate violationTimeLimitSeconds createdAt updatedAt
    nrql { query }
    terms { threshold thresholdDuration thresholdOccurrences operator priority }
    signal { aggregationWindow aggregationMethod aggregationDelay aggregationTimer
             fillOption fillValue slideBy evaluationDelay }
    expiration { closeViolationsOnExpiration expirationDuration openViolationOnExpiration }
} } } } } }
```

Verified quirks:
- Infra "host not reporting" returns empty `terms`. Its threshold is a silence duration with no NRQL term.
- `compoundConditionIds` is **not** selectable on `AlertsAsNrqlStaticCondition`. Asking for it fails the whole query.

This one query replaces three REST and Infrastructure APIs (`/v2/alerts_conditions.json`, `/v2/alerts_synthetics_conditions.json`, `/v2/alerts_location_failure_conditions/…`, `infra-api …/v2/alerts/conditions`). They are not used.

**`alerts/compound_conditions.json`** comes from `compoundConditions`. `componentConditions[].id` are NRQL condition ids from `nrql_conditions.json`. `triggerExpression` refers to them by alias.

```graphql
query ($id: Int!, $cursor: String) { actor { account(id: $id) { alerts {
  compoundConditions(cursor: $cursor) { nextCursor totalCount items {
    id name description enabled policyId triggerExpression thresholdDuration
    facetMatchingBehavior runbookUrl titleTemplate entityGuid
    componentConditions { alias id }
} } } } } }
```

### 3.3 `--alerts`: legacy channels (REST v2, the script's only REST call)

**`alerts/legacy_channels.json`** comes from `GET {api|api.eu}.newrelic.com/v2/alerts_channels.json?page=N`, with header `Api-Key: $API_KEY` (the same user key). NerdGraph has no read path for these channels. The exporter pages until a page comes back empty, with a cap of 100 pages.

- **Account attribution.** A REST v2 call with a user key reads the key's own account and cannot target another. So a channel is written for an account only when one of its `links.policy_ids` is in that account's `policies.json`. Channels linked to no policy are counted (`unattributed_channels`) and not written.
- **Redaction.** Every `configuration` value becomes `***REDACTED***`, except the allowlist `payload_type, payload, include_json_attachment, channel, recipients, teams, tags, region`. `base_url` keeps scheme and host only, with any `user:password@` removed.
- **Output shape:** `{complete, channels: [...], unattributed_channels, _note}`. `complete` is false if any REST page failed.

Unit-tested with stubbed REST responses (§5.3): Slack `url`, PagerDuty `service_key`, webhook `headers` and a credentialed `base_url` were all redacted. A channel tied to another account's policy was dropped, and the orphan was counted.

### 3.5 Five new supplemental types (`account_<id>/supplemental/`)

New flags: `--data-partitions`, `--log-obfuscation`, `--pipeline-cloud-rules`, `--key-transactions`, `--browser-apps`, each with a `--no-` form. All five are in `--all`, `--supplemental` and `--no-supplemental`; the group grows from 8 to 13.

+export_monitor_content() {

+    # SyntheticMonitorEntity. They come from actor.account.synthetics.steps /
